Notes

Four things the tables above do not say on their own.

Auth is delegated, not enumerated

/api/auth/* is mounted whole onto Better Auth's own handler behind a 30-per-quarter-hour limiter, so its routes are not declared individually and are not counted here. Sign-in, sign-out, password reset and change-password live under it; update-user, delete-user and change-email stay disabled.

One duplicate registration

PUT /api/admin/settings/:key is registered twice in admin.ts with byte-identical handler bodies. Express matches the first, so the second block is unreachable — 401 distinct routes across 402 registrations.

Stripe gates a whole block

Listing, payouts, Creator decisions, pre-order, close, refunds and disputes mount only when a Stripe gateway is configured. Without one the deployment has no money routes at all, rather than routes that would fail at the last step.

Everything else is the front end

After the API, express.static and an index.html fallback serve the SPA. An unhandled throw answers a fixed JSON body naming what is and is not known — never a stack trace, never HTML.
